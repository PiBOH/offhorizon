How it's built

Rust, checked against vanilla

The game is a new program written in Rust; the launcher is a separate Rust program. Both are built and tested in the open.

The game

Minecraft: Java Edition 26.3 is rewritten from scratch in Rust. It reads the same worlds, plays by the same rules and generates the same terrain as the Java game. It is not a mod and it does not run Java.

Checked against the real game

Hundreds of harnesses feed the same inputs to the Rust game and to the real one, then compare the results: block updates, mob behaviour, redstone, world generation. Passing them is not proof that nothing differs — players still find differences, and each one becomes a new harness.

The launcher

The launcher is its own Cargo workspace. It prepares the game folder, installs mods and packs, starts the Rust game or a Java instance, and updates itself from PiBOH/offhorizon. Game builds come from horizon-rust/horizon; the two repositories stay separate on purpose.

What OffHorizon adds

  • Offline accounts: a local name, no Microsoft sign-in gate.
  • No telemetry: the endpoint is hard-wired to nothing, so an old outbox cannot send.
  • A portable release: one file, a copy in %APPDATA%\offhorizon, and the shortcuts only if you ask for them.

Building it yourself

The repository has the build and test commands: cargo check --locked, cargo test --release --locked and cargo build --release --locked in the launcher folder for the launcher, and the root workspace for the game.
